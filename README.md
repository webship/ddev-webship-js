# DDEV Webship-JS Add-on

## Overview

This add-on integrates [Webship-JS](https://webship.co/docs/webship-js/2.0.x) — a Playwright + Cucumber-JS Automated Functional Acceptance Testing framework — into your [DDEV](https://ddev.com/) project. Write and run automated browser tests using Gherkin `.feature` files directly inside your DDEV environment.

## Installation

```bash
ddev add-on get webship/ddev-webship-js
```

This single command:

- Adds a `webship-js` layer to the DDEV web container (Playwright + browsers cached in the image).
- Restarts DDEV. On post-start the container runs `npm install --no-save webship-js` and then `init-webship-js --skip-browsers` to scaffold the project.
- Scaffolds (idempotent — preserves existing files):
  - `cucumber.js`, `playwright.config.ts`, `tsconfig.json`
  - `package.json` with `webship-js` dependency and `test`, `test:chromium`, `test:firefox`, `test:webkit`, `generate-reports` scripts (merged into existing `package.json`)
  - `tests/features/`, `tests/step-definitions/`, `tests/reports/`, `tests/selectors/`, `screenshots/`
  - Sample feature `tests/features/check-homepage.feature` (replaced once with a DDEV-universal version that passes on any project)

Sets `LAUNCH_URL=${DDEV_PRIMARY_URL}` in the web container so tests target the DDEV site by default.

Works in these install scenarios:

1. **Empty project folder** — fresh `ddev config` with no app code yet.
2. **DDEV project without `package.json`** — existing project that has never used npm.
3. **Project where `webship-js` is already installed** — re-running the add-on preserves existing `package.json` scripts, dependencies, custom `.feature` files, and custom `cucumber.js` settings.

## Install Dependencies

With npm:

```bash
ddev npm install
```

With yarn:

```bash
ddev yarn install
```

## Running Tests

With npm:

```bash
ddev npm run test:chromium      # Run all tests with Chromium
ddev npm run test:firefox       # Run all tests with Firefox
ddev npm run test:webkit        # Run all tests with WebKit
```

With yarn:

```bash
ddev yarn test:chromium         # Run all tests with Chromium
ddev yarn test:firefox          # Run all tests with Firefox
ddev yarn test:webkit           # Run all tests with WebKit
```

To run a specific feature file:

```bash
ddev exec npx cucumber-js --config cucumber.js tests/features/check-homepage.feature
```

## Reports

After a run, `tests/reports/cucumber_report.json` is produced and an HTML report is auto-generated by webship-js (set `WEBSHIP_REPORT_DISABLE=1` to skip). Regenerate manually with:

```bash
ddev npm run generate-reports
```

## Example Feature

The starter `tests/features/check-homepage.feature` verifies the DDEV site is reachable. It uses no project-specific content so it passes on any DDEV project (empty, Drupal, Laravel, Symfony, etc.):

```gherkin
Feature: Check the home page
  As an anonymous user
  I want to be able to visit the home page
  So that I know that the site is reachable

  Scenario: Check homepage is reachable
    Given I am on homepage
    Then I should be on homepage
```

## Re-scaffold or Force Defaults

The webship-js CLI is available inside the container:

```bash
ddev exec npx init-webship-js              # Idempotent — keeps existing files
ddev exec npx init-webship-js --force      # Overwrite all template files with defaults
```

## Writing Your Own Tests

Add `.feature` files under `tests/features/`. Custom step definitions go in `tests/step-definitions/`. Built-in webship-js steps include:

```gherkin
Given I am on homepage
Given I am on "/about"
When I click "Login"
When I fill in "email" with "user@example.com"
Then I should see "Welcome"
Then I should be on "/dashboard"
```

See [webship.co/docs](https://webship.co/docs/webship-js/2.0.x) for the full step reference, screenshot tags, advanced selectors, and Diffy visual-regression integration introduced in 2.0.2.
